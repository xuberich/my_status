# 🤖 Android 客户端开发与保活避坑指南

本项目主要在 **Vivo (OriginOS)** 环境下开发测试。由于国产定制 ROM 激进的后台限制，实现稳定的实时同步需要特殊设置。

## 🆘 常见问题与解决方案 (Vivo/OriginOS 专项)

### 1. 后台由于电池优化停止工作
- **现象**：锁屏一段时间后，网页不再更新，打开 App 后恢复。
- **解决**：
  - 进入 [设置] -> [电池] -> [后台耗电管理] -> 找到 [状态同步] -> 选择 **“允许高后台耗电”**。
  - 在 [最近任务] 界面，下滑 App 卡片并点击 **[锁定]** 图标。

### 2. 时长统计数据“穿越” (24h 变 27h)
- **原因**：Android `UsageStatsManager` 的统计数据基于“时间桶”，容易包含昨日数据。
- **项目对策**：本项目已全面切换为 **`UsageEvents` 事件溯源算法**。
- **原理**：直接读取从 `今日 00:00` 开始的原始日志，手动累计 `MOVE_TO_FOREGROUND` 到 `MOVE_TO_BACKGROUND` 的时长，确保绝对实时且不跨天。

### 3. 位置信息更新不及时
- **现象**：位置一直显示在几小时前的地方。
- **原因**：高德 API 在后台被系统拦截。
- **解决**：必须开启 **[后台弹出面]** 和 **[悬浮窗]** 权限。部分型号需要手动授予“始终允许访问位置信息”。

### 4. 充电状态检测延迟
- **原因**：部分机型 `BatteryManager.isCharging` 方法刷新不及时。
- **项目对策**：通过监听 `ACTION_BATTERY_CHANGED` 系统广播获取实时电流状态，比主动查询更稳健。

## 🏗️ 开发环境配置
- **Minimum SDK**: 26 (Android 8.0)
- **Target SDK**: 34 (Android 14)
- **主要依赖**:
  - `UsageStatsManager`: 用统计 APP 活跃。
  - `Sensor.TYPE_STEP_COUNTER`: 实时步数采集。
  - `NotificationListenerService`: 音乐媒体信息感知。

## ⚠️ 重要权限说明
如果你是开发者并重新编译，请确保在 App 启动页授予以下权限：
1. **使用情况访问权限** (针对统计时长)
2. **位置权限** (针对地理位置显示)
3. **通知使用权** (针对正在播放音乐)
4. **忽略电池优化** (针对后台常驻)
